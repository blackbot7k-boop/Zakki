## Dock 激活与窗口复用

### 重新打开事件缺失

`internal/app/lifecycle.go` 原先只有 `OnSecondInstance`，没有 `OnActivate`。
macOS 点击已运行应用的 Dock 图标通常发送重新打开事件，不启动第二个进程，
因此关闭主窗口后没有应用回调负责创建窗口。

独立 bundle 先复现：关闭后发送重新打开事件，5 秒后窗口创建计数仍为 1。
现在 `OnActivate` 在 `hasVisibleWindows == false` 时调用已有 `showWindow`，
保留向导优先、窗口重建、隐藏恢复和最小化恢复。

### 重建窗口时重置控件状态

提高原生回归重复次数后捕获到 `ui: a ListState shown by two Lists` 崩溃。
长期保留的 `liveList` 包含旧窗口节点/帧信息，新窗口帧号偶然一致时会触发共享状态检查。
`createWindow` 现在先调用 `resetWindowUI`：清理列表状态和旧剪贴板服务，恢复选区同步；
不清空文档或撤销历史。AppleScript 的“连接无效”可能是目标进程崩溃，不能都归因于权限。

### 顶栏 × 隐藏而不销毁

原先顶栏 × 调用 `Window.Close`，重新打开必须创建新的 UI/GPU 资源。
原生采样捕获到主线程在 Metal 的 `newRenderPipelineStateWithDescriptor:error:` →
`MTLCompilerScheduler` 同步等待；多次 GPU 测试未在 5 秒内完成初始化。
这证明驱动/管线初始化能够阻塞主线程，但不足以解释所有唤起迟滞，也不表示首窗问题已解决。

现在顶栏 × 调用 `Window.Hide`，日常唤起复用窗口及渲染资源。
⌘W 仍真正关闭窗口，退出流程不拦截关窗；隐藏的资源要到真正退出才释放。
真实点击测试确认隐藏后窗口从可见列表消失，重新打开后的原生 window ID 不变。

最终原生回归连续通过 3 轮，每轮验证 5 次关闭重建、5 次隐藏复用、最小化恢复和可见时不重复开窗。
软件渲染下关闭重建约 0.23–0.35 秒，**包含 AppleScript 进程开销，不是应用内部纯渲染耗时**。
默认 `MYGO_GPU=0` 隔离驱动初始化，不能据此保证默认 Metal 路径的端到端延迟。

```bash
ZAKKI_NATIVE_TEST=1 MYGO_LOCALE=zh-Hans \
  go test ./internal/app -run '^TestNativeDockReopen$' -count=3 -v -timeout=90s
```

## 优化前后实测

### 测量方法

- 优化前算法取自 `09fa67df21eccab9cd3e2f980bd39898cf619744` 的独立临时副本；优化后为当前工作区。
  两侧使用相同的永久 benchmark 驱动。旧 Store 仅增加可注入写入函数，以可控方式模拟慢盘；算法不变。
- 各组 **5 次独立进程采样，前后交替运行，并交替谁先运行**，避免同时跑两套基准造成争用。
  表格取 5 次中位数；原始日志保留所有样本，不只保留最快值。
- CPU 频率、系统负载和 GC 会影响绝对耗时。此前短测的高亮约 680ms → 6.7ms，最终交替测量为
  1,190ms → 11.3ms；两轮均约两个数量级改善，不应把某轮绝对值当成所有机器的保证。
- 预览为 `ui.NewTester(a.view, 400, 540)` 的真实视图帧，预热后测量；不是 Dock 点击到显示的延迟。
- MB 为十进制，MiB 为 2²⁰ 字节；撤销的 retained 指标是强制 GC 后**相对初始文档的堆增量**，不是应用总内存。

原始记录与中位数汇总：[`performance/`](performance/)。各命令每次使用 `-count=1`，按上述顺序交替重复 5 次：

### 源码高亮：消除已接受区间的平方扫描

输入为单个 Go 围栏，重复 `var x = 123 // hello`，开启代码配色。

| 代码行数 | 优化前 | 优化后 | 加速 |
|---:|---:|---:|---:|
| 1,000 | 13.69ms | 1.76ms | 7.8× |
| 2,000 | 60.73ms | 2.96ms | 20.5× |
| 4,000 | 289.28ms | 6.10ms | 47.4× |
| 8,000 | 1,189.51ms | 11.33ms | **104.9×** |

`view_highlight.go` 用每 rune 一位的占用位图替代逐个扫描已接受区间。
只检查候选覆盖的字，确认完整无碰撞后才标记；搜索优先、重叠候选整段拒绝及最终排序不变。
8,000 行约增加 21.25KiB 位图空间。随机 Unicode、跨行搜索、非法区间及 64 位边界测试
与独立旧实现 oracle 比较完整 `[]ui.TextRange`，不是只检查数量。

### 自动保存：慢写不再占用 UI 状态锁

测试在真正的临时文件写入前注入 150ms 等待，每次争用都重新建立慢写场景。

| 操作 | 优化前 | 优化后 |
|---|---:|---:|
| 慢写期间查询状态 | 151.30ms | **约 2.5µs** |
| 慢写期间提交新防抖快照 | 151.19ms | **约 4.2µs** |
| 1MiB 快照同步保存 | 3.29ms | 3.38ms |
| 10MiB 快照同步保存 | 29.18ms | 29.50ms |

收益是**隔离慢盘对 UI 的影响，不是让磁盘或 JSON 编码更快**。
`save.go` 中 `writeMu` 串行编码/写盘和写保护切换，`mu` 仅短暂保护状态。
一个保存 worker 只保留一个最新待办；新快照必须等自身防抖到期，旧 timer 不得抢先触发。

复核时还发现旧同步请求等待写锁期间可能丢弃后来接受的自动保存：补充保存修订号，
既不清除后来排队的快照，也不覆盖已先完成的新版本；新版本失败不能被旧请求掩盖。
最终保存先拒绝新请求，等待在途写入后写最终快照；并发最终保存用 `shutdownMu` 串行。
新增慢写合并、最终保存、旧 timer、直接/自动保存交错及失败传播回归；原有写保护和退出重试测试保留。

### 实时预览：减少重复派生及每帧分配

| 输入 | 帧耗时：前 → 后 | 每帧分配：前 → 后 |
|---|---:|---:|
| 1,000 行代码 | 5.98 → 3.68ms | 1.01MB → 10.9KB |
| 5,000 行代码 | 32.30 → 20.86ms | **5.01MB → 10.9KB** |
| 1,000 行双列表格 | 23.61 → 21.84ms | 2.29MB → 1.59MB |
| 5,000 行双列表格 | 126.84 → 126.25ms | 11.63MB → 8.18MB |
| 单段 100,000 个 ASCII 字符 | 101.48 → 100.48ms | 64.03MB → 46.88MB |
| 5,000 个短段落 | 0.643 → 0.324ms | 117.7KB → 19.6KB |

`live_preview_cache.go` 缓存当前块代际的投影、表格单元格/偏移、代码 spans，最多 64 块；
不存 UI Element/Context、不积累文档历史版本。文档重切、编辑、切标签失效；代码配色按完整 palette 失效。
`livePane` 和 `liveSnapshot` 复用 `mdCacheOffsets`；重建偏移表不覆写当前帧仍使用的旧切片。

代码块分配下降约 **99.8%**。但缓存**没有实现块内虚拟化**：代码仍构建全部行，表格仍构建全部 cell，
超长段落仍做全文文字布局。大表格和单段耗时基本没变，不能把减分配等同于相应幅度的帧率改善。
不同轮次代码块帧时间也有波动，不能承诺固定倍数。

### 撤销历史：保留 200 条，压缩历史小改动

1MiB 文档连续 250 次独立 IME 事务，确认历史仍为 200 条，再强制 GC：

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| GC 后堆增量 | **201.59MiB** | **1.06MiB** |
| 250 次编辑累计分配 | 264.24MB | 264.27MB |
| 独立进程计时，250 次编辑 | 148.58ms | 47.40ms |

驻留堆增量下降约 **99.5%**，但每次编辑仍创建完整新文档，累计分配并没有消失。
独立进程计时受首次堆增长影响，**不将这一行当作持续输入加速承诺**。
补测同一进程 `-count=5` 的中位数为 30.94ms → 53.24ms/250 次，即每次额外约 **0.09ms**；
这是差分扫描换取显著减少驻留的成本。补测日志也在 `performance/`，不隐去回退数据。

64KiB 起，较旧的小改动事务保存公共字节前后缀及克隆的增删片段；若接近全文替换，则保留原快照共享，
避免克隆两份巨大差分反向放大内存。两栈各自栈顶保留完整快照用于精确全文比较，
用刚验证过的相邻快照展开下一个栈顶；不靠只检查局部替换区，也不需要每次计算整篇 hash。
差分不可变，可供标签会话按值复制；弹栈清零底层槽。未减少历史深度、未扩大输入合并范围。

回归覆盖 200 步 Unicode 随机撤销/重做、250 次编辑上限、分支输入/围栏合并、
外部改写公共前后缀拒绝、跨标签复制、字节边界落在 rune 内、底层槽释放及全文替换共享。
这不是任意编辑序列的总字节上限；反复替换整篇大文档仍可能需要较多历史内存。

## 剩余瓶颈与边界

### P1：大块内部整体布局

整张表格和超长无空行段落仍是单块，外层 `ui.List` 虚拟化无法限制其内部节点/文字布局。
上述交替基准中 5,000 行表格约 126ms/帧、10 万字符单段约 100ms/帧，仍明显超出交互帧预算。
下一步应单独设计代码/表格块内按行虚拟化及超长段落布局，覆盖选择、复制、光标、IME、滚动定位和可访问性，
不能仅为跑分把内容截断或改变编辑语义。

### P2：手动及危险操作前备份仍同步

`state.go` 的 `backupNow`、清空、写回，以及删除标签的安全备份仍在主线程等待。
初次检查的本地临时目录探针中，保存加备份：1MiB 约 3.7ms、10MiB 约 31ms、32MiB 约 99ms。
本轮锁隔离不等于这些同步入口变成异步。后续应后台处理不可变快照，成功后再回主线程执行危险操作；
绝不能提前删除或清空，也不能把备份失败吞掉。

### P2：特定升级迁移累积备份正文

`datamigrate.go` 空壳新目录合并路径先读入全部旧备份，再写出。
初次探针的 64 个 1MiB 备份保留堆增量约 64.5MiB；只影响该迁移路径，不是日常泄漏。
本轮不改迁移语义，后续可单独改为元数据预检加逐文件复制/磁盘 staging，并保留回滚测试。

### 待慢卷/网络验证的风险

- 首窗前 `LoadMirrorTime` 同步扫描外部目录；设置页多次 `os.Stat(.git)`，选目录后同步可写性探测。
  路径已确认，但没有在真实失联 SMB/NFS 上测量停顿时长；下一步后台探测并缓存。
- Git runner 没有超时和取消；挂起的 push/凭证程序/hook 会占住唯一 worker。
  本地保存与退出不等待它，任务不会无限增殖，但后续镜像会等待；下一步增加非交互执行截止时间。
- 默认 Metal 首次初始化阻塞仍需真实驱动路径复验。隐藏窗口避免日常唤起重建，不能解决所有首窗驱动问题。

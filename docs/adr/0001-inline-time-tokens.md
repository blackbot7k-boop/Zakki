# 行级时间采用行内文本令牌存储

Zakki 的标签是纯 Markdown 文本，时间功能（截止/提醒）需要可导出、可 Git 同步、可在源码
模式直接编辑。我们决定：时间以行内文本令牌存储——`@YYYY-MM-DD HH:mm` 表示时刻、
`~<提前量>`（如 `~10m`、`~1h`、`~1d`）表示提醒——可附在**任意内容行**上；不引入任何
结构化行级元数据。令牌按行类型解读：任务行上是截止时间，其他行上是事情发生的时刻。
这样"文本即数据"的模型不变：导出、Git diff、外部编辑、数据文件版本（无需迁移）全部免费兼容，
提醒按实例截止时间 due 与提前量 alert 派生：必须显式带 `~`（含准点 `~0m`）、所在任务未完成
或为非任务行，且 `fireAt = due - alert` 在未来，才进入正常排定。只有 `@` 而无 `~` 不发通知。
重复令牌另受 [ADR-0002](0002-recurring-time-tokens.md) 修订节约束，先展开实例再逐实例判定。

## Considered Options

- **结构化元数据**（zakki.json 给行加字段）：拒绝——迫使每处文本操作（撤销、粘贴、合块、
  外部修改检测）维护"第 n 行"映射，破坏文本唯一事实源。
- **Emoji 令牌**（Obsidian Tasks 的 `📅`）：拒绝——在中文正文里与手写字体混排观感差，
  且源码模式视觉噪音大。
- **函数式令牌**（`@due(...)`）：拒绝——冗长，中文正文里是 ASCII 噪音。
- **仅限任务行**：拒绝——普通行也有"某时刻做事"的需求；统一令牌 + 按行类型解读
  让待办转普通列表项（摘掉勾选框）时行为自动正确，无需特判。
- 记号选择 `@`/`~` 的语义：`@` 即 "at"（在某时刻），`~` 即"约"（提前约多久）；
  Zakki 的 Markdown 解析器没有删除线等单个 `~`/`@` 语法，无冲突。

## 调度生命周期

以下例外仍要求显式 `~` 且条目符合未完成／非任务条件：

- 首次启动只排 `fireAt > now`，不补发启动前已错过的通知。
- 当前会话已排定但尚未投递的实例，若触发已到且 `now <= due + 60s`，立即投递；超过该宽限不补发。
  连续编辑跨过触发时刻仍保留已排未投递资格，使用最新正文，不因 250ms 防抖丢失。
- 会话内新增提醒若 `fireAt <= now < due`（例如 5 分钟后截止却选择提前 10 分钟），立即投递；
  新增时 due 已到的提醒不借用上述已排定宽限。
- 每 30 秒做墙钟巡检并对账重排；唤醒／激活及系统时区变化后重新核对，不能只依赖单调计时器。
  删除、改名、重读、退出失败恢复都必须更新调度代际，失效快照不得继续投递。
- 会话内投递去重键为 `tabID + 实例 due + 提前量 + 正文 hash`，记录保留 **24 小时**。
  标签改名不改变正文身份，不导致同实例重投；编辑前已排未投递资格按 tabID、due、提前量继承。
  本地去重不承诺跨设备只响一次。

## Consequences

- 时间是所在内容条目（任务、列表项、标题、引用或段落）的属性，不是正文的分界线；同一条内容使用第一个合法时间令牌，组件前后都可以有正文，输入顺序与源码位置保持不变。行尾 Split 也只检查这个首个合法令牌：只有它位于行尾才剥离；若首个在行中，不再选后面的行尾令牌。
- 通知使用同一条内容中组件前后的全部可读正文，去掉时间／提醒令牌和 Markdown 标记，链接取显示文字；不纳入其他任务或段落，不截断原始内容。修改正文后替换待触发快照。
- 预览与聚焦使用同一个行内组件；从预览进入当前条目时光标默认在整个条目末尾，后续可在组件两侧定位和输入。组件在可见编辑缓冲中是单个对象字符，映射到完整时间源码；删除、选区、剪贴板和撤销仍通过文档映射，磁盘不保存对象字符。
- 解析必须跳过围栏代码块、行内代码、链接和转义示例；表格单元格不解析（表格是独立渲染路径）。
- 文件被外部 Markdown 渲染器处理时，令牌按普通文本显示，可接受。
- 提醒调度依赖应用存活（应用内定时器 + 系统通知投递），退出 Zakki 后不提醒；
  OS 级调度（如 macOS UNCalendarNotificationTrigger）留作后续增强。
